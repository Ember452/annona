## 4. 教训

1. **假绿只有两类成因**：退出码被管道吞掉；断言采样（任何单类干净行即可通过）而非总体。门禁必须锚定聚合行，且管道必须有 `pipefail`。
2. **slice/mock 测试存在结构性盲区**：EM 的 merge/refresh 语义、事务边界、DB-default 列回读，mock EM 一概看不见。真 PG 集测是唯一防线——**集测红灯必须当真修，宁可修测试，不可放松断言**。
3. **约定靠"抄现有代码"传递会失败**：refresh 模式在 P1a-03 落地后，P1a-04 照抄时连 bug 一起抄走。项目特有语义必须进 AGENTS（每个会话必载）才有稳定传递渠道——本次进 §4 的 save/merge 约定即由此来。
4. **`SpringApplicationBuilder.properties()` 落在 defaultProperties——全部属性源里最低优先级**，会被 OS 环境变量（CI job 级 env）整体压掉。测试里要强制 profile/datasource 时用 `run(args...)` 命令行参数（优先级高于 env）。同款写法请先看 `ExtensionMissingIT` 与 `ProdProfileWithoutKekIT`（后者本就正确）。
5. **日志下载需要 admin token，匿名拿不到**：CI 失败时把摘要写成 `::error::` workflow command，checks API 匿名可读——本次整个定位闭环靠它完成，作为门禁的一部分保留。
6. **不是所有"可疑代码"都是缺陷**：`finish()` 无 `@Transactional` 是评审时写明的取舍（study_event 无消费方、事务范围最小），经复核维持原设计，补显式重评估触发条件即可（`85f07c6`）。动手前先查类 javadoc 与 ADR。
