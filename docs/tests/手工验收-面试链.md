# 手工验收 - 面试链（P1b 批 2 出口证据）

> 对应开发计划 P1b 出口条件 ①②⑤ 与批 2 计划"可截图里程碑"。**执行环境：本机**（原生 PG/Redis
> 或 dev 栈，见 AGENTS §8.3）；自动化部分的凭证：[CI run #92](https://github.com/Ember452/annona/actions/runs/36663633984)
> 六 job 全绿（含 `InterviewSessionFlowIT` 真库 5 例与 `MigrationShapeIT`）。
> 本文档做的是 CI 证不了的那半：**真模型质量与浏览器交互**。

## 0. 前置（缺一项就别开始，先补齐）

| 项 | 要求 |
|---|---|
| PostgreSQL 16 | 扩展 `vector`、`citext`、`pg_trgm`；Flyway 启动时自动迁移到 V11 |
| Redis | 可选但建议（快照与配额走它；没有则自动降级纯 DB，见冷热分层） |
| `.env` | `ANNONA_SECRET_KEY`（openssl rand -base64 32）、datasource/redis、`ANNONA_MODEL_CHAT_PROVIDER=openai-compatible` + chat Key、`ANNONA_MODEL_EMBEDDING_PROVIDER=openai-compatible` + embedding Key（**出题的向量与作答链都要真模型，这一步是本仓首次真模型全链路**） |
| `ANNONA_KNOWLEDGE_INGEST_ENABLED=true`、`ANNONA_QB_GENERATE_ENABLED=true` | 入库与出题是门控 bean，默认关 |
| 一份技术讲义 | 1–3 页 Markdown/PDF（含可出题的具体知识点，太水会触发"文档解析后没有可用文本/检索为空"路径，那也是一种有效验收——报错文案要可读） |

启动：

```powershell
.\mvnw.cmd -B -q -DskipTests package -pl annona-server -am
java -jar annona-server\target\annona-server.jar
cd annona-web; pnpm dev    # 或直接用 server 端 static 产物
```

## 1. 步骤与预期凭证（截图按编号命名贴 #17）

| # | 操作 | 预期（不满足 = 验收失败，记录现象） |
|---|---|---|
| 1 | 注册/登录 → `/knowledge` 上传讲义 | 进度条到 READY；分块数 > 0 |
| 2 | 方向绑定讲义 → `/interview` 选该方向 → 出题 3 题×2 追问 | SSE 进度"已生成 N 题"；题库列表出现 DRAFT，`scoringRubric` **成段**（不是空/一句话）——rubric 质量首跑证据 |
| 3 | 启用 ≥3 题（DRAFT→ACTIVE） | 容量校验徽章消失 |
| 4 | 面试中心：3 题、难度 3、追问 1 → 开始面试 | 返回视图含主问题+追问槽；**若池被去重清空 → 2604 文案指向"补充题库"（也算通过）** |
| 5 | 答第 1 题（主题+追问都写）→ 保存并下一题 | "已作答"标记；进度第 2/3 |
| 6 | **杀掉 java 进程 → 重启 → 刷新面试中心** | 恢复条"进行到第 2/3 题"→ 点继续 → **落在第 2 题且第 1 题答案回显**（出口②核心截图） |
| 7 | 答完 → 交卷 | 显示"已交卷：N 个作答槽落库"+ 评分占位文案；**再点一次交卷路径（DevTools 重放 POST finalize）→ 2702 文案**，库内 answer 行数不变（幂等 UI 证据） |
| 8 | `GET /api/usage/session/{sessionId}`（带 cookie） | **出题那步是 LLM 真调用 → 应有 QUESTION_GEN 场景的非零 token 账**（出口⑤）；面试本身批 2 无 LLM 调用、返回空 items 属预期，别误报 bug |
| 9 | 再开第二场（同方向同难度） | 与第一场**无重复题干**（出口①的去重半项；向量判依赖出题时的 embedding 回填，`qb_question.embedding` 非 NULL 可 SQL 抽查） |
| 10 | BYOK：`/api/llm/providers` 建 deepseek/chat 配置 + test | 列表只见掩码 `sk-…xx`；填错 Key → test 返回 2902 可懂文案；`token_usage` 与日志中**检索不到明文 Key**（`Select-String` 库 dump + 应用日志双查） |

## 2. 完成判定

10 项全过 + 截图入 #17 → 批 2 出口证据闭合；任何一项失败 → 记「步骤号 + 现象 + 服务端日志尾段」回给开发线，不要静默绕过。

## 3. 已知边界（不是 bug）

- qa 流式与向量化调用**不计入** token 账（SPI 无 usage 返回，metering-adr 决策 4）；面板口径"仅出题/评估链"。
- 评分与报告页属批 3；交卷页的占位文案是刻意的诚实设计。
- 配额默认 200,000 token/日、fail-open：演示跑不爆属预期，想看 2800 就把 `ANNONA_USAGE_DAILY_TOKEN_LIMIT` 调成小值重跑步骤 2。
