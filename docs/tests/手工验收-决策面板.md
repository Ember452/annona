# 手工验收 — 可解释决策面板（P1c-06/07/08）

> 本机无 Docker/PG（AGENTS §0.9）：本教程在**部署环境或本机原生 PG + Redis** 上执行。
> 后端 `mvn verify` 已证代码正确性；这里是端到端人工取证（真 PG 数据 + 浏览器）。

## 前置：灌 demo 历史

启动后端时加 `--annona.demo.enabled=true`（或环境变量 `ANNONA_DEMO_ENABLED=true`），
`DemoSeedRunner` 会合成 6 周历史（幂等：demo 用户已存在则跳过）。

```powershell
# 原生 PG/Redis 起法（AGENTS §8.3），参数写 .env
.\mvnw.cmd -q -DskipTests package -pl annona-server -am
java -jar annona-server\target\annona-server.jar --annona.demo.enabled=true
```

登录用 demo 账号 `demo@annona.test`（或本地注册新号，走一遍面试攒历史）。

## 验收点

### 1. 决策真的驱动组卷（P1c-05 出口）

1. 对 demo 方向发起面试（前端面试中心，或 `POST /api/interview/sessions {planMode:"auto"}`）。
2. 打开 `decision_trace` 表 / `GET /api/decision/session/{id}`：应看到 WEAK_DIRECTION（低分加压）
   与/或 FORGETTING_CURVE（久不练掺复习）留痕，且会话 `plan` 快照的难度序列与基线不同。
3. **反证**：同参数用 `planMode:"manual"` 再开一场 → `GET /api/decision/session/{id}` 返回空
   （决策未参与），难度用请求原值。

### 2. 可解释面板读懂（P1c-06 出口）

- 面试报告页底部"本场决策依据"显示每条规则的人话原因、被驳回态。
- 首页"最近面试决策依据"列出最近 5 场的理由摘要。
- 方向无学习记录时，面板显示"决策基于面试表现"（NO_STUDY_RECORD 痕），不是留白、不是报错。

### 3. 反驳改变后续决策（P1c-07 出口）

1. 对某条 WEAK_DIRECTION 留痕点"这条不对"（`POST /api/decision/trace/{id}/reject`）。
2. 重复驳同一规则累计 3 次 → `rule_reputation.disabled=true`。
3. 再开一场：`GET /api/decision/session/{id}` 不再出现该规则命中（advisor 已过滤停用规则）。

### 4. A/B（P1c-08，交部署/CI）

按 [决策 A/B 基线](../benchmarks/决策A-B_20261001.md) 跑 `scripts/ab-decision/ab.py`，把真实数字回填。

## 判定

- 4 的数字实跑前，P1 出口④记未闭合（阶段总结如实标注）。
