# annona 后期开发扩展规划（Post-v1 Roadmap）

> 这篇解决什么问题：v1（P0–P5，见 [../annona-开发计划.md](../annona-开发计划.md)）交付之后，**下一步该往哪几个方向长、哪些方向坚决不长**。
> 定位：这是候选池与准入框架，不是排期表。任何条目要变成排期，必须先通过 §8 的四问并另开 `docs/plans/` 计划。
> 状态：v1.0 草案（待 P5 结束后按真实数据修订）

---

## 1. 扩展判断的基准

v1 交付的是**闭环能转**。后期所有扩展只有三种正当性来源：

| 代号 | 正当性 | 反例 |
|---|---|---|
| **D** | 让闭环更准（决策质量、评分可信度、检索召回） | 加一个新皮肤 —— 与主线无关 |
| **R** | 让闭环传得更远（新用户群、新场景、新宿主环境） | 自研模型训练 —— 我们不训练模型 |
| **S** | 让闭环可持续（成本、运维、生态、营收） | 团队/企业权限体系 —— 单人维护者的黑洞 |

**不落在 D/R/S 任何一类的扩展，不写进本节，直接进 §7 拒绝清单。**

---

## 2. D 类：把闭环做得更准

### 2.1 决策层纵深（最高优先级）

| 扩展项 | 内容 | 价值 | 成本 | 依赖 | 判定 |
|---|---|---|---|---|---|
| **间隔重复调度器** | 用 FSRS 类算法替代当前手写遗忘曲线，按用户历史拟合半衰期，出题时按"明日到期的复习队列"驱动 | 高：把"考研/法考海量知识点"这个最刚需的场景真正接住 | M | `mastery`、`question_bank_item` | **做（v1.1 首位）** |
| 难度贝叶斯标定 | 用 `hit_rate` 与答题时长做题目难度的后验更新，形成题库自校准 | 高：让"71 分 vs 65 分"可比的根 | M | P1b-07 | **做** |
| 评分器一致性校准 | 抽样人工标注 vs 模型评分的相关性分析，出偏差报告，必要时按维度做线性校正 | 高：直接决定用户信不信分数 | M | `evaluation_result` | **做** |
| 掌握度置信区间可视化 | 面板不只给 0.58，还给"±0.15（样本量 4）" | 中：诚实性收益大于功能收益 | S | P1c-02 | 做 |
| 跨方向迁移建模 | 学过 Java 集合再学并发时，掌握度部分继承 | 低（学术上有趣，实测收益不明） | L | 需 ≥数月真实数据 | **观察** |
| 每日自动组卷 | 决策层每天早上生成"今日一张卷"，用户只回答 yes/no | 高：把产品从"要主动开面试"变成"推给你" | M | P1c + P4-05 | 做（v1.2） |

### 2.2 检索与知识纵深

| 扩展项 | 内容 | 价值 | 成本 | 判定 |
|---|---|---|---|---|
| **本地重排模型** | 用 bge-reranker 类模型替换"同模型余弦重排"，可 CPU 推理 | 高：Recall@K 之后的 Precision 提升 | M | **做**（先决条件是 P1a-09 评测证明有增益） |
| 表格与公式感知分块 | 讲义里的公式、法条编号、财报表格结构化分块 | 高：这三类恰好是非技术用户的主资料 | L | 做（v1.3） |
| 图片/扫描件 OCR 入库 | 拍照上传的题目与讲义页 | 中：移动端场景强需求 | M | 做 |
| 知识图谱化（实体—关系） | 从讲义抽概念图，面试追问沿图走 | 中：演示很惊艳，落地极易失真 | XL | **观察**（除非有 3 个以上用户实测证明检索不够用） |
| 联网检索常态化（可插拔搜索源） | 时政、法考新规、技术版本更新类问题走外部检索 | 中 | S | 做（P5 后按需） |

## 3. R 类：让闭环传得更远

### 3.1 题型与场景扩展

| 扩展项 | 内容 | 成本 | 判定与理由 |
|---|---|---|---|
| **在线判题（代码题）** | 面试出算法题，用户在沙箱写代码提交 | **XL**（沙箱隔离、逃逸防护、资源配额是独立产品线） | **观察**：技术面试刚需，但一旦做了就不是一个功能而是一条线。先靠"口述思路 + 追问"覆盖，若真实用户流失集中在此再启动 |
| 系统设计协作白板 | 画图 + AI 评架构 | L | 观察（同上，先验证文字版深度追问是否够用） |
| **英语口语与听力面试** | 复用 P3 语音链路，加英文 ASR 口音鲁棒性调优与流利度指标 | M | 做（P3 稳定后第一优先，英文复试/雅思场景明确） |
| 结构化面试题库众包 | 公务员/事业编真题型别的社区共建 | S（工程）+ 长期治理成本 | 做（走 `skills/` CC-BY-4.0 机制，不进主仓代码） |
| 无领导小组多人群面 | 真人多角色实时房间 | **XL** | **拒绝**（与 Non-goals 的 UGC/审核冲突，已用 AI 多面试官压力面替代） |
| 笔试/行测限时刷题模式 | 大量选择题 + 计时 + 排名 | M | 观察：与"面试"主线偏离，更像另一个产品；若做需独立模块而非塞进 interview |

### 3.2 宿主环境与生态

| 扩展项 | 内容 | 成本 | 判定 |
|---|---|---|---|
| **SPI 生态外扩** | 鼓励第三方实现 `Qdrant/Milvus/mongo Retriever`、`AzureOpenAI/Ollama Provider`，主仓只维护 pgvector + OpenAI 兼容 | S（需持续维护 `annona-spi` 契约稳定与文档） | **做（v1.1 起长期）**：这是开源项目最省力的扩展面 |
| **Ollama / LM Studio 本地模型一等公民** | 无 Key 也能跑（模型自动检测 + 小模型降级出题策略） | M | 做：自部署用户里"不想把笔记发给云端"的占比不低，是口碑项 |
| PWA / 移动端 | 番茄钟与打卡的移动端体验、错题复习卡片 | M | 做（P2 之后；3D 岛在移动端本就是 2D 降级） |
| Obsidian / Notion 双向同步 | 把错题本与学习笔记同步到用户自己的知识库 | M | 观察（需求真实但适配成本长期存在，优先做标准 Markdown 导出） |
| Helm Chart / k8s Operator | 生产级编排 | S–M | 观察（先确认有多人多实例部署需求） |
| 开放 API + Webhook（用户自建自动化） | 让高级用户接自己的 Notion/飞书/树洞 | S | 做（对开发者用户友好，且几乎不增加维护面） |

## 4. S 类：可持续（成本、运维、营收）

| 扩展项 | 内容 | 成本 | 判定 |
|---|---|---|---|
| **模型路由与成本优化** | 按任务复杂度自动选档（摘要用 LOW、评估用 HIGH），预算上限与成本可视化 | M | 做（托管版上线前必须完成，P1b-10 的延伸） |
| 缓存与请求合并深化 | 出题/评估的语义缓存、SingleFlight 覆盖面扩大 | S | 做 |
| 向量分片与读写分离 | 单库撑不住时的水平扩展路径 | L | 观察（触发条件见存储 ADR §何时重新评估） |
| OTel 全链路 + SLO + 特性开关 | 生产可观测与灰度 | M | 做（用户量 >1k DAU 时） |
| **托管版订阅** | 月费 + 免费额度 + 额度包；核心功能永久免费（AGPL 与拿 star 目标决定） | L（含支付、账务、客服） | 做，但**晚于**自部署口碑期 |
| 自部署支持服务 | 部署咨询、机构内网交付、定制 SKILL 包 | S（人力型） | 做：对"月费订阅"目标的现实替代，且不碰开源许可边界 |
| 团队/企业版（RBAC、组织、审计） | 多租户团队功能 | **XL** | **拒绝**（Non-goals 已定；单人维护者接不住支持工单） |
| 内容付费（题库/课程） | 卖考点内容 | M | 拒绝：内容生产是我们承诺不做的方向（设计文档主张三） |

| 扩展项 | 内容 | 成本 | 判定 |
|---|---|---|---|
| **WebRTC 替代 WS 音频中转** | 降低端到端延迟、弱网对抗 | L | 做（v1.x，取决于 P3-06 实测是否成为体验瓶颈——**用数据决定，不靠"业界都用 WebRTC"**） |
| 实时打断（barge-in）与端到端语音模型 | 更像真人对话 | M–L | 观察（延迟达标后排期） |

## 6. 国际化与可访问性

- **i18n**：v1 仅中文。触发条件：出现非中文用户提 issue 或托管版海外流量 >5%。做法：`annona-web` 引入 i18n 资源分离，后端文案进消息包（**不要提前给每条文案加 `t()`**，那是税）。
- **可访问性（a11y）**：键盘全操作、屏幕阅读器、对比度。触发条件：P2 上线即逐步补，3D 岛必须有 2D 等价视图（已在 v1 出口条件里）。
- **时区与日历**：v1 按 `user_profile.timezone`；扩展为跨时区面试日程的双方时区对照（P4 后小成本）。

## 7. 拒绝清单（写死，避免每次重新讨论）

| 事项 | 拒绝理由 |
|---|---|
| 群聊 / @AI / 任何用户生成内容广播 | 审核、举报、垃圾治理是全职工作量 |
| 神态表情分析、人脸相似度 | 生物信息合规成本，收益无法量化 |
| 徽章 / 积分 / 等级 / 打卡排行榜 | 外部激励稀释"数据驱动成长"主线；上游 summer-checkin 已自行删除 |
| workspace / team / RBAC / 企业 SSO | 支持成本黑洞，与获客路径不匹配 |
| 自研或微调模型 | 只做编排与工程 |
| 付费墙锁核心功能 | 与开源拿关注目标直接冲突 |
| ES/Milvus 作为默认依赖 | 破坏"clone 下来能跑" |
| 移动端原生 App | PWA 覆盖需求，原生需要双端维护 |
| 内置法考/CPA/考研考点内容 | 主张三：内容由用户资料驱动，不自产 |

## 8. 扩展准入四问（任何新条目进排期前必答）

1. **它属于 D / R / S 哪一类？** 三类都不是 → 直接拒绝，不进入讨论。
2. **它服务闭环主线吗？** 判据：去掉它之后，"学习数据决定面试问什么"这条链是否变弱或不变。只增装饰的不做。
3. **有实测触发条件吗？** 必须写明"出现什么数据/反馈才做"（例：真实用户流失集中在代码题 → 启动在线判题评估）。没有触发条件的条目留在观察区，不占排期。
4. **成本是 S/M/L/XL 哪一档？XL 的维护面会不会变成第二产品线？** 判据：需要新增一类基础设施（沙箱 / 多人实时房间 / 内容审核 / 支付账务）即为 XL，默认拒绝，除非有 ≥3 例真实用户为此流失。

## 9. 版本路线建议（非承诺，按触发条件浮动）

| 版本 | 主题 | 包含 |
|---|---|---|
| v1.1 | 让闭环更准 | FSRS 调度器、难度贝叶斯标定、评分器一致性校准、SPI 生态文档与 Ollama 一等公民 |
| v1.2 | 让闭环主动 | 每日自动组卷、英语口语面试、本地重排模型、开放 API + Webhook |
| v1.3 | 让知识更好读 | 表格/公式/OCR 分块、PWA 移动端、多音色 TTS、托管版配额与成本优化 |
| v2.0 | 重新评估期 | 依 §2.2/§3.1/§5 的观察项数据决定；若届时 pgvector 成瓶颈则启用 ES Retriever，若代码题需求被验证则单独立项评估沙箱 |
