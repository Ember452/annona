# ADR: 语音链路——ASR/TTS 端口落 common、独立语音会话、JSON 协议与降级路径

- 日期 / 状态：2026-10-06 / Accepted
- 相关：[P3_VOICE_PLAN](../plans/P3_VOICE_PLAN.md)、[qa-streaming-adr](2026-09-28-qa-streaming-adr.md)（StreamingChatProvider 先例）、[model-api-key-adr](2026-09-25-model-api-key-adr.md)（用途体系）、[llmprovider-metering-adr](2026-09-29-llmprovider-metering-adr.md)（scene/purpose 二维）

## 背景

P3 语音面试开工（P3-01..07）。借鉴地图 C 表点名 🅖 voiceinterview 全套为最直接借鉴源，但要求
"ASR/TTS 走 `ModelProvider` 抽象而非直连 DashScope"。现状：SPI 六端口无音频位；common 有
`StreamingChatProvider` 先例；V10 `llm_provider_config.purpose` 已含 `asr/tts` 位但零消费方；
运行时模型调用走 env 配置（BYOK 运行时解析是独立欠账，见技术债）。用户裁决：分三批、
DashScope 首实现、**独立语音会话**（不套用 interview_session）。

## 决策

1. **ASR/TTS 端口落 `annona-common`，不进 `annona-spi`**（AGENTS §4 端口判据：无第三方
   实现方需求；与 StreamingChatProvider 同先例——流式/会话语义不进对外契约 jar）：
   - `StreamingAsrProvider`：`start(options, callbacks)` 返回会话句柄（`sendAudio(byte[])` /
     `close()`），回调 `onReady/onPartial/onFinal/onError`（形状照 🅖 QwenAsrService）。
     服务端 VAD 断句；音频约定 PCM 16kHz 16bit 单声道。
   - `TtsProvider`：`byte[] synthesize(String text, TtsOptions options)` 句级一次性合成
     （🅖 QwenTtsService 同语义）；句子级并发调度是 voice 编排层职责，不是端口契约。
2. **实现只在 `annona-infrastructure`**：DashScope qwen3-asr/tts-flash-realtime 经
   JDK `java.net.http.WebSocket` 直连（不引 dashscope-sdk-java）；Fake 双实现供 CI/本机。
   装配按 ChatConfig 同款三态（`annona.model.asr/tts.provider` = none/fake/dashscope，
   默认 none），错误后移使用点、启动不拦。
3. **独立语音会话**（用户裁决）：V18 建 `voice_session`（状态机 CREATED→ACTIVE→PAUSED→
   FINALIZED/ABANDONED、direction、开场白与 ASR/TTS 配置快照、延迟指标列）。对话式面试：
   开场白可配置 + LLM 流式追问 + 多轮上下文；题库材料经 `QuestionQueryService` 只读消费
   （免白名单）。**音频不持久化，仅存转写文本**（设计 §隐私红线）。
4. **评估接入（批 2 落地，方向在此定）**：voice 交卷发布独立领域事件（不冒用
   `InterviewFinalizedEvent`——sessionId 宿主不同）；评估侧经 voice 暴露的共享只读接口
   装配会话内容，评分口径仍走 `QuestionQueryService.gradingByIds`，保证 P3-05
   "同题库得分可比"。
5. **WS 协议**：`/ws/voice`，JSON 文本帧 + base64 PCM（上行 `{type:'audio',data}` 与
   控制帧；下行 `subtitle/audio_chunk/text/control/error`，🅖 形态）。握手鉴权复用
   `IdentityProvider`（Cookie/platform/none 三模式同 SessionAuthFilter 口径）。
6. **计量**：ASR 记秒数、TTS 记字符数，借 `token_usage.prompt/completion_tokens` 列
   （purpose='asr'/'tts'，scene 增 'VOICE' 属 V11 CHECK 双处一致纪律）。**何时重新评估**：
   托管代持上线需按音频计费对账时，扩列迁移。
7. **降级路径**（P3 出口③）：TTS 不可用 → 文字面试（题干字幕仍下发）；ASR 不可用 →
   手动提交文字。LLM/ASR/TTS 任一通道未装配（none）时使用点报 `BusinessException`，
   错误码归 2600 语音段。

## 否决的备选

| 备选 | 否决原因 |
|---|---|
| 业务直连 DashScope（无端口抽象） | 借鉴地图"必须改什么"列明令禁止；换厂商（讯飞三元组）要重写业务层 |
| ASR/TTS 端口进 `annona-spi` | 无第三方实现方需求；会话/流式语义进对外契约 jar 后改一次是破坏性变更（StreamingChatProvider 先例） |
| 语音套用 interview_session（音频模态） | 用户裁决独立会话；套用需 voice→interview 写路径白名单且追问形态受 pack 约束 |
| 二进制 WS 帧 + JSON 控制帧（🅜 形态） | 省约 33% 体积但引入 pendingBinaryQueue 未就绪竞态处理；16k 单声道 200ms 块下 base64 开销可接受；有需要再切换（协议版本号预留） |
| 前端 MicVAD 客户端 VAD（🅖 引 CDN 依赖） | 设计口径是服务端 VAD 断句；省一个 CDN 脚本与 onnxruntime 依赖 |
| dashscope-sdk-java 引入 | SDK 带全量传递依赖；JDK HttpClient WebSocket 足以承载 Omni 协议；SDK 探不到的协议差异在手工冒烟校准，必要时 SDK 只进 infrastructure（端口契约不变） |

## 后果与约束

- voice 是 `modules/voice` 新顶层包（handler/session/asr/tts/audio/metrics/config/dto 子包
  按结构文档 §9）；跨模块只读消费 questionbank 的 `QuestionQueryService`（全仓免白名单先例类）。
- `annona-server` 需新增 `spring-boot-starter-websocket` 依赖（上行音频必须双向 WS）。
- 延迟埋点口径：端到端（停止说话→首包音频）是唯一对外验收数字；ASR 首字/LLM 首 token/
  TTS 首包只是链路段（设计 §10）。
- 真库行为（V18 形状、voice_session 状态机）由 docker IT 钉；DashScope 直连协议差异在
  手工冒烟校准，不进 CI。

## 何时重新评估

- 出现第二个 ASR/TTS 厂商接入（讯飞三元组凭据模型）且端口形状不够表达时；
- TTS 需要真流式（首包 <200ms 目标提级）时，`TtsProvider` 一次性语义扩为流式端口；
- 托管代持按音频量计费对账时，`token_usage` 扩时长/字符列；
- BYOK 运行时解析落地时，asr/tts 通道同批接入（现状 env 配置与 chat/embedding 同口径）。
