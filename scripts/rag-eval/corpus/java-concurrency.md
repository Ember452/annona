# Java 并发核心

## 锁升级

无锁阶段只记录 hash；出现第一次竞争后升级为偏向锁，同一线程重入只需比较线程 id。
当第二个线程来竞争时偏向锁撤销，进入轻量级锁，线程通过 CAS 把对象头指向自己的记录。
CAS 自旋超过阈值或等待线程增多，膨胀为重量级锁，未获锁的线程进入等待队列被挂起。

## volatile 与可见性

volatile 写会把缓存行写回主存并使其他核心的缓存行失效，读则强制从主存取。
它不提供原子性：`count++` 这类读改写仍需锁或原子类。
DCL 单例里的实例字段必须 volatile，否则其他线程可能看到未初始化完成的对象。

## AQS 与 ThreadLocal

AQS 用 state 变量表达同步状态，竞争失败的线程被封装成节点加入双向队列，前驱释放后被唤醒重试。
ReentrantLock 的可重入依赖 state 累加，公平锁在获取前额外检查队列中是否有前驱。

ThreadLocal 在每个线程内维护一张表，key 是弱引用的 ThreadLocal 对象，value 是强引用。
线程池复用线程时不 remove 会造成值残留，同时产生内存泄漏风险。

| 机制 | 保证 | 典型误用 |
|---|---|---|
| volatile | 可见性、禁重排 | 当作原子自增 |
| synchronized | 互斥与可见性 | 锁对象被回收 |
| CAS | 无锁比较交换 | 高竞争下 ABA 与自旋开销 |
| ThreadLocal | 线程隔离 | 池化线程不清理 |
