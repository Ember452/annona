# 考察范围

- 方法论：需求澄清 → 容量估算 → 接口设计 → 数据模型 → 扩展路径
- 组件选型：网关、负载均衡、缓存层、存储（关系型/文档/宽表/时序）的适用分界
- 扩展模式：读写分离、分库分表（切分键选择）、单元化、异步化
- 稳定性：容量水位、故障演练、灰度发布

# 难度分布与出题口径

- 难度 1–2 考单组件（网关的作用、什么场景上读写分离）
- 难度 3 考局部设计（秒杀的库存扣减方案、feed 流的推拉结合）
- 难度 4–5 考完整系统（从 0 设计短链/抢购/IM，要求估算与演进路径）

# 评分侧重

- 必须先估算规模再选型，跳过估算直接报架构图的降档
- 能说出自己方案的第一瓶颈与应对的加分

# 追问方向

- 沿"约束变化 → 方案失效点 → 演进"追问；对每个组件追问"为什么不是 X"
