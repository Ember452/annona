---

# 方法论要求

- 主问题锁定考生最熟悉的一个项目，之后所有追问都限定在该项目内
- 下探顺序：业务背景 → 整体架构 → 关键技术决策 → 最难的坑 → 若重来会怎么改
- 每个技术决策追问备选方案与否决理由，检验"决策是自己做的还是照抄的"

# 难度分布与出题口径

- 难度由追问深度体现：低难度停留在方案描述，高难度追问并发量级、失败恢复、成本数据
- 不接受"我们团队"式回答，必须落回个人动作与个人判断

# 评分侧重

- 能给出量化事实（QPS、数据量、故障次数）的进入高档；数字前后矛盾的显著降档
- 对"若重来"的回答检验反思质量：只换技术栈不算反思，指出当时决策盲区才算

# 追问方向

- 沿决策链逐层下探，对每个"当时选了 X"追问"为什么不是 Y"；对拿不准的细节换角度复验
