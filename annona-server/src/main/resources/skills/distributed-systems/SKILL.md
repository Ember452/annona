# 考察范围

- 理论：CAP 与 BASE、一致性模型（线性一致/最终一致）、时钟与顺序
- 消息队列：Kafka 分区与副本机制、RocketMQ 事务消息、消息不丢不重的实现代价
- 分布式事务：2PC/TCC/SAGA/本地消息表的适用分界与补偿设计
- 治理：限流算法（令牌桶/滑动窗口）、熔断与降级、幂等键设计

# 难度分布与出题口径

- 难度 1–2 考概念边界（CAP 取舍举例、幂等与去重的区别）
- 难度 3 考机制（Kafka 消费位移提交语义、TCC 的空回滚与悬挂）
- 难度 4–5 考架构取舍（给业务场景选事务方案并论证、消息积压的治理方案）

# 评分侧重

- 方案题必须落到"失败模式分析"：至少说清两种失败的补偿路径
- 只会堆名词不给取舍依据的低分

# 追问方向

- 沿"方案 → 失败模式 → 补偿 → 监控"下探；对声称"保证不丢"的答案追问每一段的证明
